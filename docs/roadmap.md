# 路线图：正式模型网关 + 正式对外网站

> 现状（2026-09-28）：双桶轮询原型**已验证可用**（详见
> `dual-bucket-topology.md`）。本文件记录从这个原型走向**正式生产网关**和
> **正式对外网站**的剩余工作与决策点。

## 阶段一 · 原型（已完成）

- [x] 单桶网关在两台不同出口 IP 的机器上部署并通过全部验收
      （49 单测、工具调用、思考模式、并发、崩溃自愈）。
- [x] least-connection LB 轮询双桶，per-upstream key 改写，10 单测全过。
- [x] 双桶故障转移实测无感。
- [x] 实测容量收益：并发吞吐 +20%，单请求速度**不**提升。

## 阶段二 · 正式网关（Production Model Gateway）

目标：一个 24×7、密钥受管、可观测、有容量边界的正式网关。

### 2.1 可用性
- [ ] 消除对夜间关机机器的依赖：核心 LB 与至少两个桶常开（引入第三方常开
      出口，或全部迁到常开机器）。
- [ ] 桶冗余≥2 且分属不同故障域（不同机器 + 不同出口 IP）。
- [ ] 开机自愈 + 健康告警：LB `/healthz` 已暴露每桶状态/延迟/失败数，
      接告警（cron/计划任务定时探测 + 通知）。

### 2.2 密钥与安全
- [ ] 去掉明文 key：Windows 用 DPAPI / 凭据管理器，Linux 用
      `LoadCredential`；`run.cmd` / `.env` 不再承载真实密钥。
- [ ] 正式网站对外时：客户 key 与上游 key 完全隔离，客户 key 绝不下沉到桶。
- [ ] 审计：仓库已记录"绝不记录消息内容/prompt/key"（AGENTS.md 红线），
      正式化前复查日志与 `/healthz` 输出无泄漏。

### 2.3 可观测
- [ ] 指标：每桶 QPS/延迟/失败率/日配额消耗，按 client key 维度聚合。
- [ ] 结构化日志已就绪（`LOG_FORMAT=json`），接日志聚合。
- [ ] 追踪：跨 LB → 桶 → Zen 的 request_id 贯通（当前桶侧已有 request_id，
      LB 侧待加并透传）。

### 2.4 容量与限流
- [ ] 明确免费层日配额的消耗速率与安全水位；超限前主动降级/提示，而非 429
      硬失败。
- [ ] 若 Zen 引入 session 与出口 IP 绑定，LB 加会话粘滞（当前未观察到）。
- [ ] 决定是否引入收费主链（大池）与免费池的分层路由（按 key 优先级）。

## 阶段三 · 正式对外网站（llm.223722.xyz）

目标：把上面的正式网关以多租户、可鉴权、可限流的产品形态对外。

### 3.1 入口与拓扑（**待决策，含一个明确反模式**）
- [ ] 决策点：公网入口机（吉隆坡 SWAS `47.250.130.52`）的 llmgw，上游接
      本仓库网关的哪个入口？
      - **反模式（要避免）**：让 24×7 的公网入口去依赖夜间关机的本机 LB/网关。
      - 候选 A：入口机本地重建 LB，两个桶都从入口机可达（更稳）。
      - 候选 B：桶全部放常开侧，入口机只做鉴权/限流/路由。
- [ ] Cloudflare Tunnel：现 token 缺 `Account:Cloudflare Tunnel:Read`
      （列 tunnel/读 ingress 均 401），需补带 Tunnel 权限的 token。
- [ ] 公网 SSE 需心跳保活（CF 边缘会切 idle 流，历史坑）。

### 3.2 多租户与配额
- [ ] 客户 key 体系：签发/轮换/吊销，与上游桶 key 解耦。
- [ ] 每 key 限流与日配额（防止单客户吃穿共享的免费池）。
- [ ] 模型目录与别名：对外 id 与上游真实模型解耦、语义清晰（历史偏好：
      `dsv41f` 而非 `dsv4f` 这类更贴切的命名）。

### 3.3 上线与验收
- [ ] 标准验收清单（承 `llm-relay-station` skill）：无 key 401、模型列表、
      非流式字段正确、流式 ≥2 chunk、错 key 401。
- [ ] 灰度：先内部/自用，再放开；每个阶段有明确回滚点。

## 关键决策点（需要拍板才能继续的）

1. **常开出口从哪来**——决定"正式网关"能否 24×7。候选：第三台常开机器、
   把工作负载整体迁到云、或接受夜间单机。
2. **公网入口的上游形状**——见 3.1 反模式与候选 A/B。
3. **是否引入收费主链**——免费池容量是有限且按日重置的；正式对外若需 SLA，
   需付费层兜底。
4. **免费池日配额的共享策略**——内部自用 vs 对外客户如何分配与隔离。
